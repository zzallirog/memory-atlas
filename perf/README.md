# perf/ — рендер-бенч memory-atlas

Цель юзера: **60–120 fps независимо ни от чего** (зум, окно, dpr, масштаб текста).
Это стенд, который делает такие заявления проверяемыми, а регрессии — видимыми.

## Инструменты

- **frame-bench.mjs** — матрица (вьюпорт × dpr × масштаб текста × зум-K), на клетку:
  скриптованный пан ~50 кадров, собирает
  - `js` — время draw-колбэка (rAF-обёртка, метод PERF-AUDIT-20260710);
  - `dt` — реальный rAF-to-rAF фреймтайм при `--disable-frame-rate-limit`:
    полная цена кадра (JS + растр + композит). Разрыв `dt − js` = не-JS цена;
  - объёмы канвас-вызовов (prototype-патч): arc/fill/stroke/fillText/….
  Масштаб текста ставится кликами по степперу A−/A+ (0.15/клик от дефолта 1.25).
  ```
  cd <dir-с-playwright-в-node_modules>
  node frame-bench.mjs --file ~/.cache/atlas/vault.html --label v2105 [--quick]
  ```
- **focus-cell.mjs** — одна клетка, N повторов пана, медианы по повторам:
  разброс между прогонами (термал/фон) больше многих эффектов — решают
  СМЕЖНЫЕ по времени повторы, не одиночные прогоны.
  ```
  node focus-cell.mjs <vault.html> <K> <repeats>
  ```
- **splice.py** — пересборка ГОТОВОГО vault.html с изменённым шаблоном:
  та же DATA, другой код → A/B честный по данным.
  ```
  python3 perf/splice.py ~/.cache/atlas/vault.html memory-atlas.template.html /tmp/vault-new.html
  ```
- **profile-pan.mjs** — CDP Profiler во время пана, топ self-time функций.
  Первый шаг ЛЮБОЙ перф-работы здесь — см. правило ниже.

## Грабли методики (дополняет PERF-AUDIT-20260710 §Методика)

- GPU-растр в headless НЕ мёртв: с `--enable-gpu-rasterization --ignore-gpu-blocklist
  --use-angle=gl-egl` рендерер = radeonsi (реальное железо). Бенч печатает GL renderer —
  если там SwiftShader/llvmpipe, растровая часть dt завышена, сравнивай только билды.
- **Сначала профиль, потом стройка.** Кейс 07-10: объём канвас-вызовов (~1450 arc/fill/stroke
  на кадр) выглядел очевидной целью; Path2D-бакетинг кружков срезал вызовы в 20 раз и
  ДОБАВИЛ ~2ms на обзорном зуме (native-диспатч не был ценой; запись Path2D — была).
  Реальная цена сидела в строковых КЛЮЧАХ text-metrics кэшей (конкатенация тела ~400
  символов на ноду на кадр + хэш) — 55% JS пана. Отвечает CPU-профиль, не интуиция.
- Разброс между прогонами ±20-30% — любой вывод < этого требует focus-cell с повторами.
