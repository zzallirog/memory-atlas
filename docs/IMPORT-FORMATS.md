# Импорт документов — поддержка форматов + что ломается

`atlas-serve` умеет втягивать произвольный файл в вульт (`POST /api/import`, кнопка
**＋ импорт документа** в панели «новая заметка»). Два режима:

- **convert** — файл конвертируется в markdown-тело новой ноты (движок [markitdown](https://github.com/microsoft/markitdown),
  fallback — встроенный текст-путь).
- **keep** — файл кладётся в вульт как есть, создаётся нота-обёртка со ссылкой на него.

Каждый импорт создаёт `.md`-ноту с frontmatter `tags: [imported]`, `source: <оригинальное имя>`.

## Движок

markitdown ставится в отдельный venv рядом с `atlas-serve` (`.import-venv/`); сервер
вызывает его CLI (`.import-venv/bin/markitdown <файл>`), авто-детект при старте
(лог: `markitdown: <путь>` или `markitdown: нет`). Без markitdown работает только
текст-путь (`.txt/.md/.csv/.json/.html/.xml/.yaml/...`), бинарные форматы уходят в **keep**.

## Матрица (замерено на Arch, markitdown 0.0.2, `rc` реальных прогонов)

| Формат | Convert | Результат | Что ломается / деградирует |
|---|---|---|---|
| `.txt` | ✅ rc=0 | текст как есть | — |
| `.md` `.markdown` | ✅ rc=0 | markdown как есть | — |
| `.csv` | ✅ rc=0 | текст (markitdown), таблица через xlsx-путь | без markitdown — fenced-блок, не md-таблица |
| `.tsv` | ✅ | fenced-блок | — |
| `.json` | ✅ rc=0 | ` ```json ` fence | структура сохранена, но плоско |
| `.html` `.htm` | ✅ rc=0 | markdown; `<script>`/`<style>` **вырезаны** | сложная вёрстка/таблицы могут упроститься |
| `.xml` | ✅ rc=0 | текст/fence | семантика тегов теряется |
| `.docx` | ✅ rc=0 | заголовки+абзацы (mammoth) | картинки/сноски/стили теряются |
| `.pdf` | ✅ rc=0 | извлечённый текст (pdfminer-six) | **скан без OCR = пусто**; вёрстка/колонки плывут |
| `.pptx` | ✅ rc=0 | markdown со `<!-- Slide N -->` + заголовки | графика/анимации/заметки-докладчика теряются |
| `.xlsx` | ✅ rc=0 | **md-таблицы по листам** | формулы → значения; форматирование/графики нет |
| `.png` `.jpg` и картинки | ⚠️ rc=0 но **пусто** → авто-**keep** | без OCR/LLM текст не извлекается | нужен LLM-caption или OCR (не подключён) → уходит в keep |
| `.mp3/.wav` аудио | ⚠️ зависит | транскрипт (speechrecognition) | нужен онлайн-бэкенд распознавания; иначе пусто |
| YouTube URL | ⚠️ | транскрипт (youtube-transcript-api) | не файл — URL-путь, не через эту кнопку |
| `.epub` `.zip` `.msg` | ⚠️ | markitdown поддерживает (deps есть) | не замерено в этой сессии; zip = рекурсивно |
| произвольный бинарь | ➡️ **keep** | файл в вульте + нота-ссылка | не читается в графе, нода degree 0 |

Легенда: ✅ полный текст · ⚠️ поддержан, но лоссово/условно · ➡️ уходит в keep.

## Что ломается на уровне ГРАФА (общее для всех импортов)

Атлас — граф `[[wikilinks]]` + frontmatter. Импортированный документ их не несёт, поэтому:

1. **Изолированная нода** — `degree 0`, ни одной wiki-связи. Появляется, но «висит» отдельно
   (семантические/tag-детекторы могут её позже подцепить при regen с детекторами).
2. **Зона/кластер** — попадает в указанную при импорте зону (или `imports`); без зоны — свой кластер.
3. **Теги** — только `imported` (плюс что допишешь руками на ховере/в правом баре).
4. **Бинарь (keep)** — тело ноты = ссылка на файл; **в браузере не рендерится**, открывается внешне.
5. **Размер** — большой PDF/xlsx даёт огромное тело; `.hpbody`/preview обрежут по высоте, полный текст — в правом баре/browse.

## Проверено end-to-end (эта сессия)

- `.docx` (реальный, python-docx) → `converter: markitdown`, тело `# ProofDoc … para text bold` ✅
- `.pdf` (reportlab) → текст «PDF line one / second pdf line» ✅
- `.xlsx/.pptx/.html/.csv/.json/.txt/.md/.xml` → rc=0, осмысленный markdown ✅
- `.png` convert → markitdown пусто → **авто-keep** с warnings ✅ (graceful)
- keep-режим → файл в вульте + нота-обёртка ✅
