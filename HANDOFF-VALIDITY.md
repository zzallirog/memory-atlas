# HANDOFF — валидность представления (вульт → граф) · для Opus-сессии

**Постановка (юзер, 07-09):** юзер ставит софт, генератор регенерирует ЕГО вульт в
D3-canvas UI. Как мерять, что представление валидно? Где бейслайн? Сколько рефов
проставлено, как их ставить, какая формула. Протокол должен проходиться Sonnet'ом
без экспертных суждений. Human-in-the-loop — по долгу, не опционально.

**Статус:** архитектурный драфт, НЕ построено. Опус ратифицирует/режет, потом стройка.
База: ветка `refine-20260709` (v2.4.1, `--data` валидатор уже есть — это L0 для
внешних графов; этот handoff — про scan-путь).

---

## 1. Фрейм: три поверхности, три разных «валидно»

```
вульт (.md файлы)  --parse-->  модель (nodes/edges/ghosts)  --render-->  HTML/canvas
        L0: счётная верность            L1: roundtrip                L2: смысл (детекторы)
                                 L3: human ground truth (поверх всех)
```

Сейчас меряется ТОЛЬКО хвост L1 (`data-ready="1"` + console clean) — это прокси
«скрипт дожил до конца», не «граф = вульт». Классическая дыра F2/WRONG-SURFACE.

## 2. L0 — счётная тождественность (детерминизм, ноль суждений)

**Принцип двух реализаций:** счётчик-эталон НЕ ИМЕЕТ ПРАВА использовать `WIKILINK_RE`/
`norm()` генератора — иначе метрика тавтологична (меряет свой сетап, F2). Отдельный
тупой проход: `grep -o '\[\[' | wc` уровня, своя минимальная регулярка, желательно
даже не Python-модуль генератора, а отдельный скрипт.

**Учётное тождество (главная формула):**

```
R_total = R_resolved + R_ghost + R_excluded + R_lost
  R_total    — все wikilink+mdlink токены корпуса (тупой счётчик)
  R_resolved — рёбра графа (дедуп раскрыть: считаем ТОКЕНЫ, не пары; дубли и
               self-links идут в R_excluded с меткой dup/self)
  R_ghost    — токены, ушедшие в ghost-ноды
  R_excluded — законные исключения, КАЖДОЕ с меткой: index-файл / http / self / dup / #секция
  R_lost     — остаток. ИНВАРИАНТ: R_lost = 0. Любой ≠0 = баг парсера, не «шум».
```

**Coverage** = R_resolved / (R_total − R_excluded). Не «сколько хорошо», а «сколько
учтено»: ghost — тоже валидное представление (реф без файла). Отдельно:

**Ghost-rate** = R_ghost / (R_resolved + R_ghost) — дескриптив вульта, НЕ гейт
(у Даниеля может быть законно 40%).

**Node-тождество:** `files(.md) − index − excluded_dirs = |real nodes|` (± collision-суффиксы, счёт совпадает).

Гейт L0: `R_lost = 0` И node-тождество точное. Бинарно, Sonnet-proof.

## 3. L1 — roundtrip модель↔рендер

- В HTML уже вшит DATA; экспорт full JSON уже есть (кнопка ↓ shift). Формализовать:
  `DATA.nodes/edges (по id+kind) == export.full (minus runtime-поля)` — set-равенство.
- DOM-счётчики (`#stats`: N нот / E рёбер) == stdout генератора == L0-счётчик.
  Headless-извлечение уже дёшево (`--dump-dom` + grep).

Гейт L1: три числа сходятся из трёх независимых точек (генератор / DATA / DOM).

## 4. L2 — смысловая валидность детекторов (вот где нужен НАСТОЯЩИЙ бейслайн)

Оверлап-мосты («оно нашло, что эти две заметки об одном») — value-prop. Вопрос
Фейнмана: бьёт ли детектор случайность?

**Null-модель (решение Опусу, моя рекомендация — (a)):**
- (a) **zone-shuffle**: перемешать zone-лейблы нод (degree сохранён), прогнать
  детекторы ×N=100 → распределение числа cross-рёбер по чистой случайности.
  `lift = observed / mean(null)`, p-value эмпирический. Дёшево, детерминируемо сидом.
- (b) edge-rewire (degree-preserving) — честнее для shared_ref, дороже.

**Fixture-GT by construction:** demo-вульт и gallery-вульты — мосты СПРОЕКТИРОВАНЫ
(demo: shared_ref=3, tag=1; каждый gallery-кейс аналогично). Это лейбленный GT:
recall на fixtures = 100% ожидаемых мостов найдено, 0 лишних сверх задокументированных.
Дёшево, уже в репо, гоняется в CI. ⚠ это clean-room: юзер-вульт ≠ fixtures
(урок deploy-surface-mismatch) — потому L2 на ЖИВОМ вульте = только lift-vs-null,
без абсолютных порогов.

Гейт L2: fixtures 100%/0 лишних (CI) · на живом вульте lift>1 при p<0.05 на
детектор, иначе детектор честно репортится «на этом корпусе = шум».

## 5. L3 — human-in-the-loop (по долгу)

Человек — единственный источник ground truth для «правильный ли реф» (правильно
распарсено ≠ правильно по смыслу; alias-резолюция `[[pretty-name]]`→file — класс
ошибок, который видит только читатель).

- **Стратифицированный сэмпл, малый:** K = 10 рёбер (5 wiki + 5 cross-детекторных)
  + 5 ghost'ов + 5 zone-присвоений. Правило выборки — детерминированное от сида
  (sha корпуса) → воспроизводимо, Sonnet не выбирает «удобное».
- Бинарный вопрос на каждый: «этот реф существует в тексте и указывает на ту ноту?»
  / «этот ghost правда упомянут и файла правда нет?». precision p̂ = ok/K.
- **Канал уже построен:** negatives в overlay = живая human-разметка «ребро — ложь».
  Метрика долга: `neg_rate = |negatives| / |auto cross-edges shown|` по времени —
  пассивный L3 без отдельной сессии.
- **UI audit-mode (решение Опусу, скоуп):** режим «проверь 20» — подсветить сэмпл,
  y/n на каждом, вердикт пишется в `overlay.audit` (localStorage → профиль-экспорт).
  Дёшево поверх существующей pins/lens-механики; альтернатива — чеклист в терминале.

Гейт L3: p̂ ≥ 0.9 на сэмпле (K=20 → допустимо ≤2 отказа); ниже — конкретные
отказы = вход багфикса, не «плохой вульт».

## 6. Композит vs гейты (рекомендация: гейты)

НЕ склеивать в один validity-score (веса = вкусовщина, Гудхарт). Отчёт = таблица:

```
L0 accounting   R_lost=0, nodes exact         PASS/FAIL
L1 roundtrip    3 счётчика сходятся            PASS/FAIL
L2 fixtures     мосты by-construction          PASS/FAIL (CI)
L2 live lift    per-detector lift, p           числа + флаг «шум»
L3 human        p̂ на K=20, neg_rate           число + PASS/FAIL(0.9)
```

## 7. Sonnet-протокол (исполняемость без экспертизы)

Одна команда: `memory-atlas --audit [--src DIR]` →
1) L0-счётчик (отдельная реализация) + тождество; 2) сборка + L1 roundtrip
(headless, если chromium есть; иначе DATA-vs-export без DOM); 3) L2 null-shuffle
(сид фиксирован); 4) печать таблицы гейтов + сэмпл L3 списком «покажи юзеру».
Sonnet: запустил → сравнил PASS-колонку → отдал юзеру L3-список. Ноль free-form
суждений; все пороги в коде, не в голове модели.

## 8. Решения Опусу (ranked)

1. Null-модель L2: zone-shuffle vs edge-rewire (моя ставка — shuffle, N=100, сид=sha корпуса).
2. `--audit` в генераторе vs отдельный `atlas-audit` скрипт (двух-реализационный L0
   ТРЕБУЕТ хотя бы счётчик держать отдельным файлом/модулем).
3. UI audit-mode (y/n по сэмплу в браузере) — строить или чеклист в терминале хватит.
4. Пороги: 0.9 human-precision и p<0.05 — стартовые, калибровать на НАШИХ трёх
   корпусах (memory 405 нод / demo / gallery×5) ДО того как обещать чужим.
5. Судьба neg_rate: пассивная телеметрия долга — куда репортить (dash-тайл «доверие»?).
6. CI: fixtures-L2 гейтом в матрицу (сейчас CI проверяет «строится», не «правда»).

## 9. Анти-паттерны (уже отловленные в этом репо — не повторить)

- Тавтологичный счётчик (мерить парсер его же регуляркой) — F2.
- data-ready как прокси валидности — WRONG-SURFACE, эта дыра и есть повод handoff'а.
- Clean-room числа с fixtures продавать как гарантию на живом вульте — deploy-surface.
- Композитный score вместо гейтов — Гудхарт + невозможно дебажить FAIL.
- G3-класс: аудит-кэш/отчёт общий для корпусов → cross-corpus затирание.
